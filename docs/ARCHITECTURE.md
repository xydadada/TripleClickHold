# Architecture

## 线程边界

程序由三个主要部分组成：

1. UI 线程维护托盘、热键和唯一设置窗口。
2. `MouseHookThread` 在独立线程安装低级鼠标钩子。回调只解析物理事件并入队；Mouse4/Mouse5 的按下事件通过 `BeginInvoke` 请求 UI 切换。
3. `ClickWorker` 在独立线程按计划调用 `MouseOutput`。它不在钩子回调中运行，也不等待 UI。

## 输入状态机

左右键的物理按下会被转换成 `PhysicalDown`。工作线程根据设置输出 N 次点击；启用长按保持时，最后一次只输出 Down。物理松开会产生 `PhysicalUp` 并释放最后一次 Down。

每次新的物理按下都会递增 generation。工作线程在序列和间隔之间检查 generation；发现更新就取消旧序列，必要时先发送一次 Up，随后处理最新按下，避免旧点击在队列中顺延堆积。

Mouse4/Mouse5 是专用切换键。每个按下沿只触发一次；侧键事件不传递给下层窗口，因此不会产生浏览器前进/后退。

## 配置

`TripleSettings` 是不可变快照，`SettingsState` 使用 volatile 引用在 UI、钩子和工作线程之间发布。文件写入使用临时文件再替换，读取失败时回退到默认值。设置变更先停用当前钩子状态，再重新注册热键并恢复原运行状态。

## 验证边界

`--self-check` 和 `--render-settings` 是无输入模式，可在 CI 中运行。它们验证点击计划、随机间隔范围、配置归一化和界面布局，但不能替代用户在目标游戏中的兼容性测试。
